# Feature Specification: 仕訳記録と残高試算表(Kaikei Lite 中核機能)

**Feature Branch**: `001-journal-trial-balance`

**Created**: 2026-09-07

**Status**: Draft

**Input**: User description: "個人事業主や小規模事業者の経理担当者が、日々の取引を仕訳として記録し、月末に残高試算表を確認できる財務会計ソフトを作りたい。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 仕訳を登録する (Priority: P1)

経理担当者は、日付・摘要・借方行(1 行以上)・貸方行(1 行以上)からなる仕訳を
登録する。各明細行は勘定科目と金額(円)からなる。借方合計と貸方合計が一致する
仕訳のみが登録され、一致しない仕訳は登録そのものが拒否され、差額がいくらかを
含むエラーメッセージが返る。

**Why this priority**: 仕訳の記録は本ソフトのすべての機能(一覧・試算表・元帳)の
前提となる中核操作であり、これなしに価値が生まれない。貸借一致の強制は
憲法上の非妥協項目である。

**Independent Test**: 貸借一致する仕訳 1 件を登録して成功すること、および
不一致な仕訳 1 件を登録して差額付きエラーで拒否されることで、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 空の帳簿、**When** 「現金 100,000 円(借方)/売上高 100,000 円(貸方)」の
   仕訳を登録する、**Then** 登録が成功し、仕訳が保存される
2. **Given** 空の帳簿、**When** 借方合計 100,000 円・貸方合計 98,000 円の仕訳を
   登録しようとする、**Then** 登録が拒否され、エラーに「差額 2,000 円」が含まれる
3. **Given** 帳簿に仕訳が存在する、**When** 複数の借方行(例: 30,000 円と 20,000 円)と
   複数の貸方行(例: 50,000 円 1 行)からなる仕訳を登録する、**Then** 登録が成功する
4. **Given** 空の帳簿、**When** 借方行のみ(貸方行なし)の仕訳を登録しようとする、
   **Then** 登録が拒否される
5. **Given** 空の帳簿、**When** 借方: 現金 9,223,372,036,854,775,807 円(上限値)/
   貸方: 資本金 同額 の仕訳を登録する、**Then** 登録が成功する
6. **Given** 空の帳簿、**When** 9,223,372,036,854,775,808 円(上限超過)の明細を
   含む仕訳を登録しようとする、**Then** 拒否され、仕訳は一切保存されない
7. **Given** 空の帳簿、**When** 各明細は上限以下だが合計が上限を超える、
   貸借一致する複数明細の仕訳(例: 借方 3 行ずつ 3,074,457,345,618,258,669 円)を
   登録する、**Then** 登録が成功し、試算表・元帳の集計でも正確な合計・残高が
   表示される

### User Story 2 - 登録済みの仕訳を日付順に一覧する (Priority: P2)

経理担当者は、登録したすべての仕訳を日付順で一覧表示し、各仕訳の日付・摘要・
借方明細・貸方明細・金額を確認できる。

**Why this priority**: 記録した仕訳を確認できなければ、記録が正しく行われたことを
利用者が検証できない。試算表・元帳に先行する基本的な確認操作である。

**Independent Test**: 日付の異なる仕訳を 2 件以上登録し、一覧が日付順に
全仕訳を表示することで、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 日付の異なる仕訳が 2 件登録されている、**When** 仕訳一覧を表示する、
   **Then** 2 件が日付順(古い日付が先)で表示される
2. **Given** 同じ日付の仕訳が 2 件登録されている、**When** 仕訳一覧を表示する、
   **Then** 2 件とも表示され、登録順が保たれる
3. **Given** 仕訳が 1 件も登録されていない、**When** 仕訳一覧を表示する、
   **Then** 空であることがわかる表示が返る(エラーではない)

---

### User Story 3 - 残高試算表を表示する (Priority: P2)

経理担当者は、開始日と終了日を指定して残高試算表を表示する。科目ごとに
借方合計・貸方合計・借方残高・貸方残高が示され、最後に全科目の合計行が出る。
借方合計と貸方合計は必ず一致する。

**Why this priority**: 「月末に残高試算表を確認する」は本ソフト導入の主目的であり、
日々の仕訳記録の価値を確定させる集計機能である。

**Independent Test**: 仕訳を数件登録した後、期間を指定して試算表を表示し、
科目ごとの集計値と合計行の貸借一致を手計算と突き合わせることで、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 期間内に「現金 100,000(借方)/売上高 100,000(貸方)」の仕訳がある、
   **When** その期間の試算表を表示する、**Then** 現金行は借方残高 100,000、
   売上高行は貸方残高 100,000 を示す
2. **Given** 期間内に複数科目にまたがる仕訳がある、**When** 試算表を表示する、
   **Then** 合計行の借方合計と貸方合計が一致する
3. **Given** ある期間に仕訳が存在しない、**When** その期間の試算表を表示する、
   **Then** 全科目が 0 で合計行も 0・0(貸借一致)の試算表が表示される
4. **Given** 期間内の仕訳と、期間外(開始日より前・終了日より後)の仕訳が
   両方存在する、**When** 試算表を表示する、**Then** 借方合計・貸方合計の列は
   期間内の仕訳のみで集計され、残高列には開始日以前の繰越高が含まれ、
   終了日より後の仕訳はどの列にも反映されない
5. **Given** 資産・費用科目(例: 現金、仕入高)に仕訳がある、**When** 試算表を表示する、
   **Then** これらの科目の残高は借方に出る
6. **Given** 負債・純資産・収益科目(例: 買掛金、資本金、売上高)に仕訳がある、
   **When** 試算表を表示する、**Then** これらの科目の残高は貸方に出る
7. **Given** 現金の貸方発生が借方発生を上回る仕訳群がある、**When** 試算表を
   表示する、**Then** 現金行は貸方残高に正の金額を表示し、借方残高は 0 である
8. **Given** ある科目の借方発生と貸方発生が一致している、**When** 試算表を
   表示する、**Then** その科目の借方残高・貸方残高はともに 0 である

### User Story 4 - 総勘定元帳を表示する (Priority: P3)

経理担当者は、勘定科目を 1 つ指定して総勘定元帳を表示する。開始日と終了日も
指定できる。その科目が関わる明細が日付順に並び、各明細には相手科目と、
その科目の累計残高(借方・貸方の別を明示)が付いて表示される。

**Why this priority**: 特定科目(例: 現金)の増減の内訳を追跡したいという
補助的な確認ニーズに応える。試算表があれば最低限の確認は可能なため、
優先度は一段下げる。

**Independent Test**: 同一科目が複数回出てくる仕訳を登録し、元帳を表示して
明細が日付順で、各明細に相手科目と累計残高が付くことで、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 現金を借方とする仕訳が 2 件(相手科目: 売上高、資本金)ある、
   **When** 現金の元帳を表示する、**Then** 2 明細が日付順で表示され、
   各明細に相手科目(売上高/資本金)が付く
2. **Given** 現金を借方とする仕訳が複数ある、**When** 現金の元帳を表示する、
   **Then** 各明細に、その明細までの現金の累計残高が付く
3. **Given** 現金が借方にも貸方にも登場する仕訳がある、**When** 現金の元帳を
   表示する、**Then** 借方明細と貸方明細が区別して表示され、累計残高は
   両者を差し引きした値が続く
4. **Given** 指定した科目が期間内のどの仕訳にも登場しない、**When** その科目の
   元帳を表示する、**Then** 空であることがわかる表示が返る(エラーではない)
5. **Given** 開始日より前の仕訳と期間内の仕訳の両方がある、**When** 期間を指定して
   元帳を表示する、**Then** 開始日以前の累計が繰越高として最初の期間内明細の
   累計残高に反映される
6. **Given** 期間を指定せずに元帳を表示する、**When** 元帳を表示する、
   **Then** 全期間の明細が表示される
7. **Given** ある時点で借方発生と貸方発生が打ち消し合っている、**When** その明細以降を
   含む元帳を表示する、**Then** 該当明細の累計残高は「残高 0(貸借区分なし)」として
   表示される

### User Story 5 - 逆仕訳で仕訳を訂正する (Priority: P3)

経理担当者は、誤った仕訳を削除せず、元の仕訳を打ち消す逆仕訳(取消仕訳)を
登録して訂正する。逆仕訳は「どの仕訳を訂正したものか」が一覧と元帳上で
わかる。訂正後の正しい仕訳は新規の仕訳として登録する。

**Why this priority**: 誤記の訂正は実務上必要だが、正しい仕訳登録が先に
存在すれば、訂正はその運用で補完可能なため優先度を下げる。会計の原則として
データを消さない記録の連鎖を保つ。

**Independent Test**: 仕訳を 1 件登録してから逆仕訳を作成し、一覧上で
両者が対応付けされて表示され、試算表の集計で両者の影響が打ち消し合うことで、
単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 借方: 現金 100,000 / 貸方: 売上高 100,000 の仕訳 A がある、
   **When** 仕訳 A に対する逆仕訳を作成する、**Then** 借方: 売上高 100,000 /
   貸方: 現金 100,000 の仕訳が作成され、仕訳 A と対応付けられて表示される
2. **Given** 逆仕訳が作成されている、**When** 仕訳一覧を表示する、**Then**
   逆仕訳には元の仕訳への参照(取消元の識別子)が表示される
3. **Given** 仕訳 A とその逆仕訳がある、**When** 試算表を表示する、**Then**
   両者の影響が打ち消し合い、仕訳 A が存在しなかった場合と同じ集計になる
4. **Given** すでに取消済みの仕訳 A、**When** 再度仕訳 A の逆仕訳を作成しようと
   する、**Then** 二重取消として拒否される
5. **Given** 仕訳 A に対する逆仕訳(取消仕訳)B を間違えて登録した、**When**
   逆仕訳 B を取り消す(その逆仕訳を作成する)、**Then** 取消が成功し、
   仕訳 A は引き続き取り消済みのままである
6. **Given** 逆仕訳の作成時に摘要を省略する、**When** 仕訳 A の逆仕訳を作成する、
   **Then** 摘要は「仕訳 #A の取消」(A は取消元の番号)が設定される

---

### Edge Cases

- 借方行または貸方行が 0 行の仕訳 → 登録を拒否する
- 金額が 0 円の明細行 → 登録を拒否する
- 金額が負の値の明細行 → 登録を拒否する(円単位の正の整数のみ)
- 1 明細の入力金額が 1 円未満または 9,223,372,036,854,775,807 円超過 →
  明確なエラーメッセージで拒否する
- 複数明細の合計・繰越高・残高が入力上限を超える → 上限検査の対象外
  (正しく計算・表示する)
- 入力エラーが発生した仕訳 → 全体が保存されない(一部の明細だけ残らない)
- 摘要が空文字・空白のみ → 登録を拒否する
- 標準科目に存在しない科目名・科目コードの指定 → 登録を拒否する
- 金額に小数(例: 100.5 円)が指定された場合 → 受け付けない(円未満の入力はエラー)
- 存在しない仕訳を指定して逆仕訳を作成しようとした場合 → エラーになる
- 開始日が終了日より後の期間指定 → エラーになる
- 存在しない日付(例: 2026-02-30)の指定 → エラーになる
- 元帳で累計残高が 0 になった明細 → 「残高 0(貸借区分なし)」と表示する
- 試算表で仕訳が一切ない科目 → 0 で表示するか全科目行として必ず出す
  (全 10 科目を常に表示する)
- 同日の複数仕訳がある元帳 → 登録順に累計残高が積み上げられる

## Clarifications

### Session 2026-09-07

- Q: 誤った仕訳を取り消す逆仕訳には、どの日付を設定すべきでしょうか? → A: 逆仕訳の日付は取消実行日を既定値とし、利用者が指定できる。元の仕訳の日付は変更せず、各仕訳はそれぞれの日付が属する期間の集計に反映する。
- Q: 逆仕訳の登録を間違えた場合、その逆仕訳自体をさらに取り消すことはできるべきでしょうか? → A: 可能。逆仕訳も通常の仕訳と同様に、その逆仕訳を作成して取り消せる(元仕訳への再取消は引き続き拒否)。
- Q: 残高試算表の集計で、開始日と終了日の境界はどう扱うべきでしょうか? → A: 両端を含む(開始日当日と終了日当日の仕訳はどちらも集計に含まれる)。
- Q: 開始日より前の仕訳がある場合、試算表にはその仕訳の影響(繰越高)をどう反映すべきでしょうか? → A: 開始日より前の仕訳の累計を繰越高として残高列に含める。借方合計・貸方合計の列は期間内集計のまま、残高列のみ繰越高を反映する。
- Q: 1 つの明細行に入力できる金額の上限はどうするべきでしょうか? → A: 上限を設けない(0 より大きい整数であれば任意の金額を受け付ける)。

### Session 2026-09-07 (checklist review)

- Q: 貸借不一致のエラーに「貸借のどちらが多いか」の表示も求めるか? → A: エラーには差額を表示する。どちらが多いかの表示は必須としない。
- Q: 摘要の必須性と空文字の扱いは? → A: 摘要は必須とし、空文字・空白のみはエラーにする。
- Q: 「取消実行日」の取得基準は? → A: 日本時間(Asia/Tokyo)の当日とする。逆仕訳の日付はこれを既定値とし、利用者による指定も可能とする。
- Q: 逆仕訳の摘要を省略した場合の既定値は? → A: 「仕訳 #対象番号 の取消」を設定する。
- Q: 残高が区分の発生側と逆側に回った場合の表示は? → A: 試算表は実際の差額に応じて借方残高または貸方残高に正の金額を表示する。元帳も残高の借方・貸方を明示する。
- Q: 残高が 0 の場合の表示は? → A: 試算表の借方残高・貸方残高は両方 0 とし、元帳は残高 0・貸借区分なしとする。
- Q: 総勘定元帳にも期間指定を設けるか? → A: 設ける。開始日・終了日は両端を含み、開始日より前の繰越高を累計残高に反映する。
- Q: 日付の入力形式と不正値の扱いは? → A: YYYY-MM-DD とし、存在しない日付や開始日が終了日より後の場合はエラーにする。
- Q: 金額の上限なしは保存・集計まで技術的に実現可能か? → A: SQLite の 64bit 符号付き整数の範囲(最大 9,223,372,036,854,775,807 円)までを上限とするよう仕様を変更(案 B)。範囲外の金額は明確なエラーメッセージで拒否する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、日付・摘要・1 行以上の借方行・1 行以上の貸方行からなる
  仕訳を登録できる(MUST)。各明細行は勘定科目と金額を持つ。摘要は必須とし
  (MUST)、空文字・空白のみの摘要は受け付けない(MUST NOT)。
- **FR-002**: システムは、借方合計と貸方合計が一致しない仕訳の登録を拒否し、
  差額を含むエラーを返す(MUST)。不一致の仕訳が保存される経路を
  作ってはならない(MUST NOT)。貸借のどちらが多いかの表示は必須としない。
  また、入力エラー(貸借不一致・未定義科目・金額の検査違反など)の際は
  仕訳全体(全明細行)を保存せず(MUST)、一部の明細だけが残っては
  ならない(MUST NOT)。
- **FR-003**: システムは、金額を円単位の整数としてのみ受け付ける(MUST)。
  1 明細の入力金額は 1 円以上 9,223,372,036,854,775,807 円以下の整数とし
  (MUST)、浮動小数点としての金額入力を受け付けてはならない(MUST NOT)。
  この上限は 1 明細の入力金額にのみ適用し(MUST)、複数明細の合計・
  繰越高・残高の集計結果には適用しない(MUST NOT)。集計結果がこの値を
  超えた場合も、正しく計算・表示できる(MUST)。
  上限を超える入力金額は明確なエラーメッセージとともに拒否する(MUST)。
- **FR-004**: システムは、標準科目 10 科目(現金、普通預金、売掛金、買掛金、
  借入金、資本金、売上高、仕入高、給料、通信費)をあらかじめ用意する(MUST)。
- **FR-005**: 各科目は資産・負債・純資産・収益・費用の区分を持ち、区分ごとに
  残高の発生側が次のように定まっている(MUST): 資産・費用 → 借方、
  負債・純資産・収益 → 貸方。
- **FR-006**: システムは、登録済みのすべての仕訳を日付順(同日付は登録順)で
  一覧表示できる(MUST)。
- **FR-007**: システムは、既存仕訳を打ち消す逆仕訳(取消仕訳)を作成でき(MUST)、
  逆仕訳は取消元の仕訳への参照を保持し(MUST)、削除元の仕訳は削除されない
  (MUST)。逆仕訳の日付は取消実行日(日本時間(Asia/Tokyo)の当日)を既定値とし
  (MUST)、利用者が指定できる(MAY)。摘要を省略した場合の既定値は
  「仕訳 #<取消元番号> の取消」とする(MUST)。元の仕訳の日付は変更されず
  (MUST)、各仕訳はそれぞれの日付が属する期間の集計に反映される(MUST)。
- **FR-008**: すでに取消済みの仕訳を取消元として、再度逆仕訳を作成することは
  拒否される(MUST)。逆仕訳自体は通常の仕訳と同様に、その逆仕訳を作成して
  取り消せる(MUST)。
- **FR-009**: システムは、開始日と終了日の指定で残高試算表を表示できる(MUST)。
  集計期間は開始日と終了日の両端を含み(MUST)、存在しない日付や開始日が
  終了日より後の指定はエラーとする(MUST)。科目ごとに借方合計・貸方合計・
  借方残高・貸方残高を示し、最後に全科目の合計行を含む(MUST)。
  借方合計・貸方合計の列は期間内の仕訳のみの集計とし(MUST)、残高列は
  開始日より前の仕訳の累計を繰越高として含む(MUST)。終了日より後の仕訳は
  どの列にも反映されない(MUST)。残高は、借方と貸方の差額に応じて残高が
  発生している側に正の金額で表示する(MUST)。残高が 0 の科目は、
  借方残高・貸方残高ともに 0 を表示する(MUST)。
- **FR-010**: 試算表の合計行において、借方合計と貸方合計は常に一致する(MUST)。
- **FR-011**: システムは、科目を指定して総勘定元帳を表示できる(MUST)。開始日と
  終了日の指定を設け(MAY)、期間は両端を含み(MUST)、開始日より前の仕訳の
  累計を繰越高として累計残高に反映する(MUST)。期間を指定しない場合は

### Key Entities *(include if feature involves data)*

- **勘定科目**: 科目コード、科目名、区分(資産/負債/純資産/収益/費用)、
  残高の発生側(借方/貸方)。標準 10 科目はあらかじめ定義済み。
- **仕訳**: 識別子、日付、摘要、借方明細行の集合(1 行以上)、貸方明細行の
  集合(1 行以上)、取消元仕訳への参照(取消仕訳の場合のみ)。
  貸借一致は保存の前提条件。
- **明細行**: 勘定科目への参照、金額(円・正の整数)。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 貸借不一致の仕訳は 100% 登録拒否され、その際エラーメッセージに
  差額の金額が含まれる(試験仕訳での確認率 100%)
- **SC-002**: 経験なき経理担当者が、案内だけで最初の仕訳を 1 分以内に
  登録できる
- **SC-003**: 1,000 件の仕訳から残高試算表を生成したとき、合計行の貸借一致が
  100% 保たれ、手計算した 10 件の科目集計とすべて一致する
- **SC-004**: 取消済み仕訳とその逆仕訳の対応が 100% 一覧・元帳上で確認でき、
  二重取消が 100% 拒否される
- **SC-005**: すべての機能がコマンドラインから実行でき、表形式と JSON 両方の
  出力が取得できる(機能カバレッジ 100%)

## Assumptions

- 利用者は経理担当者 1 名。ログイン、複数人同時利用、消費税の計算、
  決算処理(締め仕訳・財務諸表の作成)は本機能の対象外。
- 標準科目 10 科目は固定であり、ユーザーによる科目の追加・変更・削除は
  本機能の対象外とする。
- 金額は円単位の正の整数のみ。円未満(小数)の金額は扱わない(憲法原則 II)。
- データは 1 台の環境に保存され、他システムとの連携は本機能の対象外
  (JSON 出力は確認・検証用)。
- 試算表・元帳の残高は、借方と貸方の差額に応じて残高が発生している側に
  正の金額で表示する(区分の発生側と一致しない残高も実額の側に表示する)。
- 日付の入力形式は YYYY-MM-DD とし、存在しない日付は受け付けない。
  「取消実行日」の既定値の解釈は日本時間(Asia/Tokyo)の当日とする。
- 収益・費用科目の残高も、資産・負債・純資産と同様に繰越高を含む残高列の
  ルールに従う(期間に依存しない「期残高」の管理は対象外)。
